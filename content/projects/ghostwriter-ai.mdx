## The problem

Writing a good LinkedIn post takes more steps than it looks: checking the idea is worth posting, picking a format, writing a hook, designing a carousel. Generic AI writers skip most of them, and it shows.

## The approach

GhostWriterAI gives each step its own agent. Five agents (validator, strategist, writer, visual designer and optimizer) pass a typed state to one another on the Gemini API, and the app streams each agent's progress to the browser as it works.

- **39+ REST endpoints** behind the web app: auth with email verification, brand profiles, post generation, history and analytics.
- **50+ active users and 200+ generations** since launch, self-funded.
- Each user has a brand profile (voice, audience, content pillars, sample posts) that is fed to every agent.
- Structured prompting with Pydantic output schemas cut token use by **40%**.

## Architecture

A React and Vite single-page app calls a FastAPI backend. Generation is a two-phase flow: the validator and strategist run first and stop with clarifying questions, then after the user answers, the writer, optional visual designer and optimizer run. Each phase starts as an asyncio task inside the API process, and its events go into a queue that the SSE response reads from.

PostgreSQL (async SQLAlchemy, Alembic migrations) stores users, brand profiles, posts and a full per-agent history, including every event the stream emitted. Verification emails go out over SMTP through Brevo.

## The pipeline

The graph is small on purpose. The validator can reject an idea and end the run. The strategist always pauses the graph so a human can answer questions. After writing, only carousels go through the visual agent, and the optimizer can send the draft back to the writer, at most twice.

```python title="backend/src/orchestration/graph.py"
def route_after_optimizer(state: AgentState) -> str:
    """Route based on optimizer decision."""
    decision = state.get("optimizer_output", {}).get("decision", "APPROVE")
    revision = state.get("revision_count", 0)
    max_rev = state.get("max_revisions", 2)

    if decision == "REVISE" and revision < max_rev:
        state["revision_count"] = revision + 1
        return "write"
    return "finalize"
```

Capping revisions keeps the loop from burning tokens chasing a perfect score. Every agent also sits behind a shared base class that times the call, retries on failure with a growing delay, and returns a structured result.

  The streamed path calls the agent nodes one by one so it can emit an event around each, while the compiled LangGraph is used for the non-streaming endpoints.

## Shipping it

Backend and frontend deploy separately, with a Dockerfile for the API and GitHub Actions workflows for tests and deploys. Alembic migrations track schema changes, and pytest covers agents, the database layer and an end-to-end generation flow.
